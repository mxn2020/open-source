# Governance

## Maintainers

This monorepo is maintained by the core team. As projects are split into separate repositories, each will have its own governance structure.

## Decision Process

1. **Minor changes** (bug fixes, small features): Single maintainer approval
2. **Significant changes** (new features, API changes): Two maintainer approvals
3. **Breaking changes**: RFC process with community input period (minimum 1 week)
4. **New projects**: Proposal via GitHub Discussion, core team approval

## Becoming a Maintainer

1. Consistent, high-quality contributions over 3+ months
2. Demonstrated understanding of the project goals and conventions
3. Nomination by an existing maintainer
4. Approval by majority of existing maintainers

## Conflict Resolution

1. Attempt to resolve through discussion on the PR/issue
2. Escalate to maintainer group discussion
3. If unresolved, majority vote among maintainers
4. Final escalation to project lead
